# Agent Note: omp agent importer

Status: implemented

## Problem

OMP stores agent usage in pi-compatible transcripts, including side-channel
calls and Devin adaptive routing metadata. Ignoring these records or the
upstream model hides usage and attributes routed requests to `adaptive`.

## Decision

Added `model.Omp` ("omp") as the eleventh agent.

- **Schema shared with pi.** `~/.omp/agent/sessions/**/*.jsonl` uses the same
  record family as pi: `session` (v3), `model_change`,
  `thinking_level_change`, `title`, `title_change`, `message`, `custom`.
  The `omp()` parser mirrors `pi()` usage fields
  (`usage.input/output/cacheRead/cacheWrite/cost.total`).
- **Session id falls back to the filename.** omp transcripts are named
  `<createdAt>_<session-id>.jsonl` and a `{"type":"title"}` record can
  precede the `session` record, so `newFileParser` takes the UUID suffix
  after the last `_` to avoid an orphan file-id session.
- **Titles.** `session.title`, `title`, `title_change` and the first user
  `message` all feed `Session.Title`; explicit title records win.
- **Dedup by responseId.** `message.responseId` (fallback: record `id`)
  becomes `DedupKey`, deduped per session. Forked sessions that copy a
  parent prefix under a new session id still count separately — pi parity.
- **`ttft`/`duration`** on assistant messages map to `TTFTMs`/`TotalTimeMs`;
  pi does not populate these.
- **`model_usage` records count too.** `find`/`auto-thinking`/`judge` calls
  (e.g. `typesafe/jev-latest`) log usage outside the `message` stream; each
  becomes a turn with `ContextStream = "purpose/<purpose>"` and
  `DedupKey` = record `id`.
- **`thinking_level_change.thinkingLevel`** maps to `AgentMode`, like pi.
- **Devin adaptive routing.** Keep `message.model` as `SelectedModel` and
  `message.upstreamModel` as `RealModel`, reusing Devin's
  `adaptive → <real model>` session display. Each turn's `Model` uses its
  own upstream ID with the configured provider prefix; never substitute the
  last session model for earlier turns. OMP's `devin/adaptive` selection is
  recognized alongside Devin's bare `adaptive`. Like Devin, the usage table
  marks adaptive-routed turns with `(adaptive)`; independent
  `model_usage` calls retain their own labels. Missing upstream metadata
  remains adaptive without borrowing a previous turn's model; model changes
  clear stale `RealModel`.
- **Adaptive is the billing model, upstream is display metadata.**
  `Turn.BillingModel` retains `devin/adaptive` for OMP and `adaptive` for
  native Devin sessions, while `Turn.Model` remains the per-turn display ID.
  Both pricing entry points use the published Devin adaptive rates even when
  a transcript carries an estimated cost for another model. Non-adaptive
  recorded costs keep their existing precedence. Auxiliary `model_usage`
  calls and native Devin's `compactor` keep independent billing. The optional
  field survives sync and participates in turn identity; absent fields retain
  the existing identity hashes and protocol versions. Snapshot version 6
  reparses earlier results so no upstream-priced adaptive turns remain cached.
- **Skills only, no MCP target.** omp loads `~/.agents/skills` (inherited,
  like pi/codex) and gets a dedicated `~/.omp/agent/skills` column; no omp
  MCP config file was found in `~/.omp` so no MCP target is declared.
- **No Rust counterpart.** `src/` never imported omp; excluded from the
  migration differential on purpose.
- Verified against real `~/.omp` history: `go run . --cli --agent omp`
  produces sessions, models (`devin/swe-2`, `opencode-go/deepseek-v4-flash`),
  cache reads and recorded costs.

## Alternatives considered

Reusing pi's parser alone loses OMP titles, response deduplication, timing,
side-channel calls and upstream models. Inferring earlier turns from the
session's last real model combines distinct routed models incorrectly.

## Consequences

OMP uses a backward-compatible optional billing field in the session/turn
synchronization format. Session rows
and details share Devin's adaptive display; old transcripts without upstream
metadata remain readable. The first load after the cache version change
reparses local history.

## Regression coverage

- `internal/data/data_test.go::TestOmpAdaptiveModels` covers per-turn routing,
  adaptive billing, side-channel isolation, old messages, model changes and
  invalidation of an otherwise fresh version-5 cache.
- `internal/pricing/pricing_test.go::TestAdaptiveBillingIgnoresDisplayModelAndRecordedEstimate`
  checks both pricing entry points against the adaptive rates across different
  upstream IDs, including missing, zero and positive recorded estimates.
- `internal/data/data_test.go::TestDevinAdaptiveBilling` keeps native Devin's
  display model independent of adaptive billing and excludes its compactor.
- `internal/desktop/visual_test.go::TestAdaptiveSessionModelDisplay` renders
  both Devin and OMP session lists/details with the same adaptive labels,
  including older sessions without upstream metadata.
