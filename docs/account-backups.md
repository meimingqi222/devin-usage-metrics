# 账号导入、导出与加密同步

支持应用中已保存的 Claude Code、Codex、Antigravity 和 Grok 备用账号。导出不扫描其他应用的凭证目录，也不包含 GitHub 同步登录。

## 本地备份和迁移

1. 在“实时配额 → 账号”或“设置 → 常规偏好 → 管理账号”中打开账号管理。
2. 点击“导出账号”，选择 `.aumaccounts` 文件，输入并确认至少 10 个字符的口令。
3. 在另一台设备启用账号切换，点击“导入账号”，选择文件并输入口令。
4. 查看解密后的账号预览，点击“导入备用账号”确认。

导入只增加缺失的备用账号，已有账号的凭证保持不变，当前 Agent 登录也不会切换。手动导入可恢复之前在本机删除的备用账号。系统文件选择框支持保存位置和覆盖确认。备份中的 Antigravity 凭证会转换为目标平台的存储形状。

文件使用 AES-256-GCM 加密并验证完整性，PBKDF2-SHA256（600,000 轮、独立随机盐）从口令派生密钥，每次导出使用新的随机 nonce。口令不写入文件、配置或日志。忘记口令后无法恢复。当前文件格式为版本 1，最多 512 个账号，密文文件上限 16 MiB。

## 跨设备账号同步

1. 升级 `sync-server` 到包含账号备份能力的版本。原有用量同步协议和设备 ID 不变。
2. 每台设备登录同一同步 API 下的同一 GitHub 账号，并启用本机账号切换。
3. 在“设置 → 多设备同步 → 加密账号同步”点击“启用 / 解锁”。确认显示的同步 API 和 GitHub 账号，输入相同口令。
4. 解锁后立即同步；后续跟随应用既有同步周期运行，也可点击“立即同步账号”。口令只保留在当前进程，应用重启后需要再次解锁。

账号同步默认关闭，与用量同步独立授权。锁定会清除当前进程中的口令并取消进行中的账号同步；停用还会关闭自动账号同步。切换同步 API、退出或重新登录 GitHub 时需要重新启用。关闭账号切换也会锁定账号同步。

服务端只保存每台设备的一份加密账号快照。客户端先验证所有快照能用当前口令解密，再上传自己的快照；口令错误或文件损坏时不上传、不导入。多台设备各自写入自己的对象，避免并发上传互相覆盖。新设备遇到同一账号的多个副本时，优先使用凭证修改时间较新的副本；已存在于本机的凭证始终保留。

删除备用账号只影响本机，并记录本机忽略标记，后续同步不会把它自动恢复。删除不会删除其他设备或服务器上的加密副本。停用同步也保留服务器中的密文。需要恢复本机已删除的账号时，可使用手动文件导入。

账号导入与同步不保证各 Agent 的授权永久有效；部分服务会撤销或轮换刷新令牌，跨设备激活后如授权失效，需在目标设备重新登录。同步不会自动激活账号，也不会覆盖已运行会话的登录。

## 服务端兼容与诊断

新版服务器提供经过现有 GitHub 同步认证的 `GET /v1/capabilities`，返回 `account_backups: 1`。客户端检查此能力后才上传账号。旧服务器仍可同步用量，但客户端会提示升级服务器后再启用账号同步，避免旧 GC 清理账号快照。

账号快照使用独立的 `accounts-v1-<device-hash>.json` 对象，经过现有租户认证及存储配额控制，不写入用量 head/manifest。GC 将合法账号快照作为保留根。客户端对数量、文件名、文件大小、格式及解密后的凭证类型进行验证。

登录诊断和账号同步阶段写入现有 `sync.log`，只记录固定阶段、错误分类和数量。Windows 路径为 `%LOCALAPPDATA%\devin-usage-metrics\sync.log`。不会记录口令、授权 URL、授权码、邮箱、Token 或凭证正文。
