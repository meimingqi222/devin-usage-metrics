# 模型价格 JSON 与计费逻辑排查（2026-10-13）

## 本次差额的确切来源

2026-10-11 的原始日志，用量与 ccusage 完全一致：输入 1,204、输出 222,236、缓存写入 3,072,894、缓存读取 74,641,329，总计 77,937,663 token。

| 项目 | 修复前 | 修复后 / ccusage |
| --- | ---: | ---: |
| 费用 USD | 27.85178730 | 23.31790880 |
| Sonnet 5.5 缓存读取单价 USD / 百万 token | 0.20 | 0.10 |

Sonnet 的缓存读取量为 45,338,785。差额为 `45,338,785 / 1,000,000 × (0.20 - 0.10) = 4.53387850`，恰好解释全部费用差异。Opus 与 Sonnet 的 ccusage 分项费用分别为 10.46742080 和 12.85048800。修复后的程序已直接读取同一批本机日志，得到 23.31790880。

## JSON 应该怎样理解

价格源为 `https://models.opencode.ai/api.json`，本次分析使用本机 2026-10-13 的原始缓存，SHA256 为 `8B44B72330AF2C251A915776B2A8A4FF5B1A0D3126BE682E5A366AEF0D3B1362`。

结构是 `供应商 → models → 完整 model ID → cost`，不是一张全球统一的“模型名 → 官方价格”表。

| 字段 | 含义 | 查价时的用途 |
| --- | --- | --- |
| 最外层供应商键 | 报价渠道，如 anthropic、openrouter、venice | 保留为计价来源 |
| models 的键 | 渠道内完整模型 ID，可以包含作者命名空间、部署变体或资源路径 | 与供应商组合后精确查询 |
| canonical_model_id | 模型身份及作者线索 | 辅助定位原厂；不能把渠道价格变成原厂价格 |
| cost.input / output | 普通输入 / 输出单价，USD / 百万 token | 逐轮乘以对应 token 数 |
| cost.cache_read / cache_write | 缓存读取 / 写入单价 | 缺失与显式 0 必须区分 |
| cost.tiers | 带明确上下文阈值的阶梯报价 | 按该轮完整 prompt 选择阶梯 |
| cost.context_over_200k | 历史兼容字段 | 名称可能对应 272K；不能据名字推断阈值 |
| limit.context | 模型窗口容量 | 不是计费阈值 |
| input_audio / output_audio / reasoning | 特殊类别的价格 | 普通文本统计不能冒充这些类别的独立计费 |

例如 `openrouter` 里的 `anthropic/claude-sonnet-5-5`，实际渠道是 OpenRouter，`anthropic` 是模型命名空间。对应完整查询键为 `openrouter/anthropic/claude-sonnet-5-5`。丢掉 OpenRouter 后，无法恢复实际渠道。

冲突包括 Claude、GPT、Gemini、DeepSeek、Kimi、GLM、MiniMax、Qwen 及其他家族。同一供应商内部还可能同时提供普通部署和 TEE 部署，其模型尾名相同，但报价不同。因此“优先处理 Anthropic”或“找一个最便宜的渠道”均不能作为通用修复。

修复后的提取结果保留 9,800 个完整渠道查询键及默认别名，其中 1,674 个裸模型名有可用默认价格，642 个没有可靠默认价格（包括冲突报价、来源不明的全零占位）。这不影响已知渠道的精确查询。对所有 8,114 个报价及其显式阶梯逐项核对，提取前后基础单价、阶梯单价和供应商均为零不一致。

## 采用的查价规则

1. 有有效的日志自报费用时，沿用它；缺失费用不能变成 0，非法数值也不能直接汇总。不同 agent 的占位 0 需要按其日志语义处理。
2. Devin 用量使用独立的官方 Self-serve/Pro 表，保留 SWE-2 促销日期及已发布的 GPT-5.6 长上下文规则。其他 agent 使用 API 报价表，不能回退到 Devin enterprise 价格。
3. API 查价先查完整原始 `供应商/完整 model ID`。精确价格优先于命名转换，避免把某渠道的 `gpt-5-1` 改写成另一个报价不同的 `gpt-5.1`。
4. 裸模型名优先使用已确认的原厂报价。作者元数据不足或存在全球/区域接口时，用小范围的模型家族来源规则补充身份判断；这里不保存硬编码单价。
5. 没有可确认原厂时，仅在候选报价一致且非全零占位时保留默认估价，并记录实际报价来源。存在冲突则返回未知，不根据 JSON 顺序、最低价或最高价选择。
6. 保留同一渠道内的完整部署名；不会把 `vendor/model` 和 `TEE/model` 合并。也不会把转售商的模型命名空间注册成该原厂的渠道报价。
7. 仅支持明确的别名转换（如 Fireworks 资源路径、旧 GPT 版本写法），且保留渠道。已知 GPT/Claude 思考后缀可以在无独立报价时继承基础价格；Fast、Pro、新版本、免费版等未知变体必须有自己的报价。`max` 不能对所有家族通用：Qwen Max 可以是独立型号。
8. 按单轮 `普通输入 + 缓存读取 + 缓存写入` 选择最大的已超过的显式 context 阈值；不把日累计量当成单轮上下文。阶梯缺失的费率继承基础费率，显式 0 保留。只有旧 context 字段而无明确阈值时，不猜阈值。
9. 有缓存用量但相应价格缺失时，该轮价格未知，不能按免费计算。Claude 缓存写入区分 5 分钟和 1 小时；1 小时按该轮输入单价的 2 倍计算。
10. 成功加载完整目录时替换旧表，移除已经失效的默认别名。无来源信息的旧拍平缓存失效并重新获取；下载或解析失败保留最后有效数据。内嵌离线快照采用相同规则生成。

## 一并修复的日志与模拟问题

- Claude 的 `cache_creation: {}` 或部分分档对象不能擦掉 `cache_creation_input_tokens` 总量。缺少分档的余量沿用旧格式规则，归入 5 分钟写入。
- MimoCode 保留 `providerID`，即使 `modelID` 已带作者命名空间；只避免同一个供应商前缀重复添加。
- Pi 保留供应商及原始模型身份，区别“没有 cost.total”与显式 `cost.total: 0`，以便缺失费用可以继续查价。
- OpenCode 的旧版及 v2 数据库保留有效非零自报费用；其用于“尚未计价”的 0 仍允许继续查价，行为与 MimoCode 对齐。
- 用量缓存版本从 12 升至 13，让旧解析结果重新加载。
- 压缩建议模拟使用 API 价格来源，并逐次按模拟 prompt 选择阶梯，避免报告费用与建议模拟采用不同费率。

## 验证与重现

`tests/audit_pricing_catalog.py` 扫描原始 JSON 的结构及冲突；`examples/pricing_catalog.rs` 使用实际 Rust 提取器核对所有渠道报价与阶梯，也可重新生成离线快照。

```powershell
python -X utf8 tests/audit_pricing_catalog.py <原始-api.json>
cargo run --example pricing_catalog -- <原始-api.json>
cargo run --example pricing_catalog -- <原始-api.json> src/models-dev-pricing.json
cargo test -- --test-threads=1
cargo fmt --check
```

回归测试覆盖：原厂与转售报价冲突、完整渠道、同渠道部署冲突、精确 ID 优先、未知变体、所有离线渠道查询键的往返解析、阈值边界、缺失缓存价格、显式零价、失效默认价格清理、无效刷新保留旧数据，以及 Claude、MimoCode、Pi、OpenCode 的日志解析问题。

最终全量运行：189 项测试通过，3 项原有环境依赖测试按既有配置跳过；格式检查、diff 检查及构建通过。生成器重新导出的价格快照与提交文件哈希一致。常规 regression-notes 验证通过；额外 strict-anchors 检查发现一条既有 Antigravity 记录引用了已不存在的测试 `antigravity_windows_client_pairs_config_references`，该记录及配额代码未在本次修改。

## 能保证什么

本次验证覆盖这个完整目录的报价提取、来源选择和程序支持的文本/缓存费用计算，并核对了报告中的真实 Claude 日志；不等于逐一核实 227 家的商业合同。models.dev 是当前公开报价聚合，不能还原所有历史涨价、账户折扣、订阅额度、地区计费或特殊音视频价格。日志缺少实际渠道或 token 类别时，无法推出唯一真实账单；报告应保留未知或公开标价估算，而不能伪造精确性。
