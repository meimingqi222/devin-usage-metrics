# 全项目性能优化工作记录

目标：覆盖同步客户端/服务端、数据导入与查询、统计聚合、界面重绘和修改代码的维护性。既有协议、设备身份、历史改写检测、价格语义和原生 UI 行为须保持。当前任务尚未完成；下面明确区分已验证与待完成。

## 已实施的第一批改动

- 同步发布的会话排序预先计算 wire identity，排序时移动键和记录，避免比较器反复建映射与 SHA-256。固定 2000 会话基准三次：原版 21.11–24.33 ms、35.74 MB/op、265020 allocations；新版 0.78–0.85 ms、0.88 MB/op、5902 allocations。这是排序阶段，不代表同步端到端耗时。保留既有排序比较关系，未知 agent 映射行为不变。
- 同步每个分组仅计算一次内容 hash，匹配旧 references 和编码使用同一值。
- 用量页将总计和唯一会话数纳入已有 bucket 缓存；数据变化、agent、设备、翻页、跨日期、价格更新失效路径共用。移除 hover/图表模式重绘时对全部 turns 的重复扫描。会话标识使用已有结构化 identity。
- 新增排序 differential test 与可复用基准；新增用量缓存输入失效/零分配测试。

本机原始基准日志：`/private/tmp/aum-sync-sort-before.log`、`/private/tmp/aum-sync-sort-after.log`、`/private/tmp/aum-usage-cache.log`。本轮未进行真实账号同步或网络写入。

2. 查询/统计：大历史、跨设备、不同时间窗口的聚合成本与价格查找热点，保持自然日期/DST和费用语义。

## 第二批：发布周期与压缩器生命周期

- 无变化周期（12000 本地 + 12000 远端轮次）基线：模拟服务无额外延迟约 14.6 ms；每请求加 20 ms 延迟约 102.8 ms；3 GET/周期，0 数据块 GET。该基准不访问真实账号。
- 发现每个 shard 都创建 Zstd encoder。改为单次 publish 拥有一个惰性 encoder，独立 EncodeAll 后在 publish 返回时 Close；无变化、不需编码的发布不分配 encoder，不增加全局缓存。
- 单块基准（500 会话 JSON）：原版 0.425–0.431 ms、18.63 MB/op，新版 0.053–0.056 ms、约 0.206 MB/op。连续不同分块输出与 fresh encoder 逐字节相同，并可独立解压。
- 完整周期，200 会话/6000 轮次/30 天，模拟 HTTP 服务，三次：首次发布 **35.10 → 27.43 ms**（约下降 22%），分配 **87.64 → 37.01 MB**；单轮增量 **21.87 → 21.39 ms**，未主张显著收益。这个对照只改变压缩器复用，双方都包含第一批排序优化。
- 同步客户端 race 与发布/兼容/压缩回归通过。待最终全仓验收；尚未更新安装包。
- 日志：`/private/tmp/aum-publication-before.log`、`/private/tmp/aum-publication-after.log`、`/private/tmp/aum-compress-before.log`、`/private/tmp/aum-compress-after.log`。

统计基线已建立：10 万轮次、1000 会话、365 天的 Devin 历史，日页聚合约 2.66–2.71 ms，月页覆盖年度约 35–37 ms。下一步沿实际 profile 分析聚合与价格解析，而不是凭复杂度判断收益。

## 第三批：统计/定价聚合

Profile 显示年度聚合约 36% CPU 在 pricing.Cost。已把每轮 token 计费与模型报价解析分离，共用同一计费函数；聚合和会话费用使用局部 Calculator（最多 256 个 agent/model 项），缓存命中和未找到的报价。两处运行时价格表替换均递增受锁保护的版本，现有 Calculator 在下次调用失效；缓存不保存最终费用，仍逐轮处理 token/context tier、缓存时长和 recorded cost。

统计只保留实际使用的模型名/adaptive 标志，不再在映射中复制整条 Session、逐轮调用 DisplayModel。缺少会话、重复会话的最后一条优先和跨设备身份保持原语义。

同一 10 万轮次基准：日页约 2.66–2.71 → 2.45–2.48 ms，分配 1.51 → 1.16 MB；年度月页约 35.03–36.70 → 30.90–31.16 ms，分配 6.82 → 6.47 MB。这些是内存聚合耗时，不含数据库加载或 UI 绘制。新增测试覆盖所有 agent 的报价缓存/单次价格对照、token 阈值、recorded zero/invalid、模型 fallback、价格更新后的已知报价和负缓存失效、256 项上限；原有分层定价与 DST 回归继续使用。

服务端已发现下一候选：重复不可变对象的条件 PUT 在判断 412 前仍写临时文件并 fsync。准备测量提前检查的收益；必须保留最终 CAS 检查、body hash 验证和损坏对象修复行为，尚未修改服务端。

## 第四批：服务端重复上传与会话列表

512 KiB 重复不可变对象上传，三次基准从 7.11–7.84 ms 降至 0.529–0.630 ms。提前拒绝仅用于 body/hash 校验后、不可变对象、create-only 请求；读取当前实际 ETag，损坏对象仍可 If-Match 修复，新对象仍最终持锁验证 CAS。服务器 race 22 tests 与 vet 通过；制造旧行为的回归测试失败证据已保存。

会话列表把现有筛选/排序结果缓存到数据、搜索、设备及显示隐藏项/子代理设置变化为止；saveSessionUI 和 allData 数据重建均失效。空搜索不再为每条记录拼接/小写文本。最多持有 500 条可见记录，避免切片背后保留整个筛选数组。原生桌面回归及 race 通过；新增测试验证搜索、隐藏、回收站、远端数据、设备筛选和无变化零分配。
